# Contrat global de collaboration — CooLabVR
Seule la branche `main` existe dans le processus de travail. Aucun PR, branche intermédiaire, demande de confirmation ou attente du programmeur avant son commit. Tous les rôles publient directement sur `main` les fichiers de leur périmètre, synchronisent la tête courante avant l'écriture et conservent les autres modifications.
La mission et les comportements existants sont des contraintes de conservation : le silence du billet n'autorise pas une dégradation. Aucun changement de définition du résultat, de tests ou de références pour masquer une régression. La conformité statique ne prouve ni compilation ni comportement.
Le programmeur écrit le code et son signal de livraison. QA inspecte statiquement le diff et le code, jamais les captures. Un refus QA ou un échec réel de compilation/démarrage est transmis directement au programmeur ; aucune escalade automatique à l'architecte. Après QA conforme, seul le propriétaire lance le diagnostic local et publie ses preuves. L'architecte est réveillé uniquement après diagnostic complet vérifié sur le même SHA ; il examine alors QA, les images, les métriques et le fonctionnement. L'architecte décide seul de l'acceptation, du correctif ou du recul du code. Un recul se fait par nouveau commit de réversion sur main, sans effacer l'historique ni les preuves.
La source de vérité est GitHub : chaque signal porte cycle_id, billet, source_sha et tentative. Aucun nombre maximal de tentatives, aucune date butoir et aucun critère de progression fictif. Le propriétaire conserve la validation finale dans son casque.

Pour voir le pull et le diagnostic local en direct dans RelaisAgents, le propriétaire démarre une fois `local_relay.bat` sur sa machine Windows. Ce serveur de lecture seule écoute uniquement 127.0.0.1 et ne lance aucune opération Git. Sans cette passerelle, l'extension ne peut observer que les commits GitHub, pas les processus locaux.
